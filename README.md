# Семейный квиз «Ванин первый большой квиз»

Готовый Flask-сервис для первого дня рождения: все гости видят один и тот же вопрос, сервер отсчитывает 60 секунд, ведущий может отключить таймер и переключать вопросы вручную. Ответы, прогресс, раунды и рейтинг хранятся в SQLite.

## Что уже работает

- общий для всех вопрос и серверный таймер на 60 секунд;
- автоматический переход после истечения времени;
- ручной режим: ведущий отключает таймер и нажимает «Следующий вопрос»;
- свободный ввод в первых четырёх вопросах с мягким распознаванием времени, месяцев, граммов/килограммов и сантиметров;
- один неизменяемый ответ на вопрос, повтор запроса не начисляет баллы повторно;
- начисление от 1 до `N` баллов за близость в вопросах со свободным вводом;
- в вопросах с выбором верный вариант получает 2 балла, неверный или пропущенный — 0;
- восстановление сессии в том же браузере;
- рейтинг с одинаковыми местами при одинаковом счёте и обновлением раз в 10 секунд;
- конфиденциальное пожелание Ване после финального вопроса и закрытый архив пожеланий в `/admin`;
- защищённый паролем пульт `/admin`, QR-код, CSV для Excel;
- открытие/закрытие приёма ответов и новый чистый раунд;
- CSRF-защита, подписанная Flask-сессия и серверная проверка всех ответов;
- адаптивный русский интерфейс без CDN и без сборки фронтенда.

## Структура

```text
app/                  Flask-приложение, шаблоны, CSS, JS и SVG
config/quiz.json      настройки и закрытые правильные ответы
tests/                серверные и конкурентные тесты
run.py                только локальный запуск
wsgi.py.example       пример WSGI для PythonAnywhere
requirements.txt      production-зависимости
```

База не лежит в репозитории. Текущий раунд хранит снимок JSON-конфигурации, поэтому редактирование вопросов не меняет уже начавшуюся игру. Новая версия вопросов применяется после действия «Очистить и создать раунд».

## Локальный запуск

Нужен Python 3.10 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
export FLASK_SECRET_KEY="$(python -c 'import secrets; print(secrets.token_hex(32))')"
export ADMIN_PASSWORD='придумайте-надёжный-пароль'
export QUIZ_DATABASE="$PWD/instance/quiz.sqlite"
export SESSION_COOKIE_SECURE=false
flask --app run:app init-db
flask --app run:app run
```

Откройте `http://127.0.0.1:5000/`, пульт ведущего — `http://127.0.0.1:5000/admin`.

Инициализация выполняется и при старте приложения; команда `init-db` полезна как явная проверка. Она безопасна для существующих данных и не очищает их.

### Тесты

```bash
pytest -q
```

Тесты используют временные базы и не затрагивают локальную или production-базу.

## Вопросы и система баллов

В `config/quiz.json` уже записаны десять настоящих вопросов из брифа. Первые четыре имеют тип `numeric`. В браузере JavaScript-маски приводят ответы к единому виду: `ЧЧ:ММ`, целые месяцы, граммы и сантиметры. Сервер дополнительно сохраняет мягкое распознавание (`2210`, `3,15 кг`, `0,51 м` и другие варианты) как страховку для старой страницы или повторного запроса.

После каждого ответа счёт пересчитывается с учётом текущего количества гостей `N`:

- в числовых вопросах ближайшая догадка получает `N`, следующая — `N−1`, самая далёкая — не меньше 1;
- одинаково близкие ответы получают одинаковые баллы;
- в вопросах с вариантами верный ответ получает 2 балла, остальные и пропуски — 0;
- ведущий не является участником и в `N` не входит;
- если новый гость присоединился позже, сервер пересчитывает баллы; максимальный итог равен `4 × N + 12`.

Тексты ошибок намеренно дружелюбные: приложение пытается понять ответ и просит исправление только когда значение невозможно безопасно сравнить.

### Как изменить вопросы

Откройте `config/quiz.json` и измените:

- `child_name`, `title`, `subtitle`, `welcome`;
- `event_date`, `final_title`, `final_text`;
- `question_seconds` (сейчас 60);
- десять объектов в `questions`;
- `demo_content` — сейчас уже `false`.

У каждого вопроса должны быть уникальный `id` и текст. Для `choice` нужны минимум два варианта с уникальными `id` и один `correct_option_id`. Для `numeric` нужны `answer_kind` и числовой `correct_value`. Вопросов должно быть ровно 10. При ошибке приложение не создаст новый раунд и покажет понятную причину в error log.

Пример настоящего вопроса:

```json
{
  "id": "first-word",
  "type": "choice",
  "text": "Какое слово Ваня сказал первым?",
  "caption": "",
  "image": "/static/uploads/first-word.jpg",
  "options": [
    {"id": "mama", "text": "Мама"},
    {"id": "papa", "text": "Папа"},
    {"id": "av", "text": "Ав-ав"}
  ],
  "correct_option_id": "av"
}
```

Пример вопроса со свободным вводом:

```json
{
  "id": "birth-weight",
  "type": "numeric",
  "answer_kind": "weight_grams",
  "text": "Сколько Ваня весил при рождении?",
  "caption": "Введите вес в граммах",
  "placeholder": "3150",
  "image": "",
  "correct_value": 3150
}
```

Фотографии положите в `app/static/uploads/` и укажите путь `/static/uploads/имя-файла.jpg`. Не кладите семейные фотографии в публичный GitHub-репозиторий, если не хотите сделать их публичными. Правильные ответы находятся только в серверном JSON и в снимке раунда в SQLite; публичные API их не отдают.

После изменения JSON войдите в `/admin`, введите `ОЧИСТИТЬ` и создайте новый раунд. Старый раунд архивируется, сохранённые cookies гостей не ломают новую игру.

## Порядок проведения

1. Ведущий входит на `/admin`.
2. Нажимает «Открыть вход», гости сканируют QR-код и вводят имена.
3. Нажимает «Начать с 1-го вопроса» — у всех запускаются общие 60 секунд.
4. Если нужен разговор без отсчёта, нажимает «Выключить таймер».
5. В ручном режиме перелистывает кнопкой «Следующий вопрос»; кнопка «Запустить 60 секунд» снова включает отсчёт для текущего вопроса.
6. После десятого вопроса следующий переход завершает раунд и открывает результаты.

Закрытие квиза останавливает таймер и приём ответов, но сохраняет прогресс. После повторного открытия таймер остаётся выключенным: ведущий сам включает 60 секунд или продолжает вручную.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `FLASK_SECRET_KEY` | Длинный случайный секрет подписи сессий, обязателен |
| `ADMIN_PASSWORD` | Пароль страницы `/admin`, обязателен |
| `QUIZ_DATABASE` | Абсолютный путь к SQLite |
| `QUIZ_CONFIG` | Абсолютный путь к `quiz.json`; необязателен локально |
| `SESSION_COOKIE_SECURE` | `true` на HTTPS, `false` только локально |

Сгенерировать секрет:

```bash
python -c 'import secrets; print(secrets.token_hex(32))'
```

Не коммитьте `.env`, WSGI-файл с настоящими секретами, базу и CSV гостей.

## Резервная копия SQLite

Перед праздником и перед крупным обновлением:

```bash
mkdir -p /home/nkprs/quiz-backups
sqlite3 /home/nkprs/quiz-data/quiz.sqlite ".backup '/home/nkprs/quiz-backups/quiz-$(date +%Y%m%d-%H%M).sqlite'"
```

Для восстановления сначала закройте квиз, сделайте ещё одну копию текущего файла, затем замените базу проверенной копией и нажмите **Reload**. Не копируйте активно изменяемую базу обычным `cp`; команда `.backup` создаёт согласованную копию.

## Ограничения и эксплуатация

- Одна попытка привязана к подписанной cookie текущего браузера. Удаление cookies или другое устройство позволяет войти повторно.
- SQLite работает в консервативном режиме `DELETE`, с короткими транзакциями и ожиданием блокировки до 8 секунд. Это подходит для небольшого семейного квиза и постоянного диска PythonAnywhere.
- Автопереход не требует фонового процесса: первый клиентский polling после дедлайна атомарно переводит общий раунд дальше. Гости опрашивают состояние раз в 2 секунды.
- Архивные раунды остаются в базе для целостности; CSV и рейтинг показывают только текущий раунд.
- Пожелания не попадают в публичный рейтинг или API. Их видит только вошедший ведущий; в CSV они экспортируются вместе с результатами.
- За несколько дней до праздника войдите в PythonAnywhere и продлите срок активности бесплатного Web app, если в интерфейсе появилась такая кнопка. Сделайте повторную проверку ссылки, QR-кода и HTTPS с двух телефонов.
